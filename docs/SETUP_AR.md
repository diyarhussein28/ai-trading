## 3) جيب المفاتيح

### أ) مفتاح Anthropic (إلزامي)
1. ادخل **console.anthropic.com** وسجّل حساب.
2. من **Billing** اشحن رصيد، وحط **حد شهري للصرف (Spend limit)** تحت **Limits**، مثلاً $20 للبداية.
3. من **API Keys** اضغط **Create Key** وانسخه. يبدأ بـ `sk-ant-...`.
4. **لا تشاركه مع أحد، ولا ترفعه على GitHub.**

> التصويت يستخدم `claude-haiku-5-5`، وهو رخيص وسريع. الدروس بعد كل صفقة تستخدم `claude-opus-5-5`. التكلفة الفعلية تشوفها في لوحة البوت تحت **التكاليف مقابل الربح**.

### ب) مفتاح X API (عشان يتداول فعلاً)
1. ادخل **developer.x.com** وسجّل كمطوّر بحساب X (**حساب حقيقي ونظامي**، مو حساب وهمي).
2. سوّ **Project** وجوّاه **App**.
3. من **Keys and tokens** انسخ **Bearer Token**.
4. **مهم جداً:** شوف سعر قراءة المنشورات في خطتك (developer.x.com ← Pricing). بعدها افتح `config/v7.yaml` وعدّل:
   ```yaml
   social:
     est_usd_per_post: 0.015    # 0.005$ للمنشور + 0.010$ لصاحب المنشور (أسوأ حالة)
     hourly_budget_usd: 2.0     # أقصى صرف بالساعة
     daily_budget_usd: 20.0     # أقصى صرف باليوم
   ```
   هذي الحدود هي اللي تمنع تكرار مشكلة الـ −$40 في 12 دقيقة اللي صارت في الفيديو.

> **ما عندك X؟** عندك خيار ثاني: افتح `config/v7.yaml` وغيّر `social.on_missing` من `pass` إلى `degrade`. وقتها المحقق والقنّاص يحكمون من روابط العملة في DexScreener فقط (X/Telegram/موقع)، وأعلى درجة يعطونها 75.
> هذا **تغيير في الإستراتيجية**، فلازم تغيّر `version` بعد (مثلاً `V7-degrade`).

### ج) بوت Telegram للتنبيهات (مستحسن)
1. في تيليجرام افتح **@BotFather** واكتب `/newbot`، واختار اسم. يعطيك **Token** شكله `123456:ABC...`.
2. افتح البوت الجديد واكتب له أي رسالة، مثلاً `hi`.
3. افتح هذا الرابط في المتصفح بعد ما تحط التوكن مكان `<TOKEN>`:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
   دوّر على `"chat":{"id": 123456789` في النتيجة. هذا الرقم هو **TELEGRAM_CHAT_ID**.

### د) رابط Solana RPC (اختياري)
1. ادخل **helius.dev** وسوّ حساب مجاني.
2. انسخ رابط **Mainnet RPC**، شكله `https://mainnet.helius-rpc.com/?api-key=...`.

### هـ) كلمة سر للوحة التحكم (إلزامية على Railway)
بدونها أي أحد عنده الرابط يشوف لوحتك. ولّد وحدة عشوائية بهذا الأمر:

```bash
openssl rand -hex 24
```

### قبل كل شيء: افحص المفاتيح

```bash

```

يختبر كل مفتاح (Anthropic، وX، وTelegram، وRPC، وقاعدة البيانات) مع خدمته، بطلبات **مجانية** وبدون ما يطبع أي مفتاح. لازم يطلع **كل شيء جاهز ✅**. لو فيه ❌، السطر نفسه يقولك وش تصلّح.

### أ) جرّب عملة وحدة يدوياً
خذ عنوان أي عملة من dexscreener.com/solana (العنوان الطويل اللي آخره `pump`):

```bash

```

يطبع لك هل العملة نجحت في الفلتر وبوابة الأمان، وليش.

### ب) شغّل البوت

```bash
.venv/bin/python -m app.main run
```

افتح: `http://localhost:8080/?token=كلمة_السر`

**وش المفروض تشوف أول 10 إلى 30 دقيقة:**
- رقم **إطلاقات شافها** (فوق في الشريط) يزيد باستمرار. ما يزيد؟ معناه الاتصال بـ PumpPortal فيه مشكلة.
- في قسم **مسار الفلترة** الأرقام تنزل بشكل حاد. هذا طبيعي: آلاف الإطلاقات، يمكن عشرات تنجح في الفلتر، وقليل جداً يعدّي الأمان.
- قسم **العملات المرشّحة** يكتب سبب قبول أو رفض كل عملة بالعربي. هنا تفهم ليش البوت ما يشتري.
- أول صفقة ممكن تتأخر **ساعات**. هذا مقصود: الإجماع 3/3 صعب الإقناع.
- تيليجرام يوصلك 🟢 لما يبدأ البوت، و🟢 فتح صفقة، و✅/❌ إغلاق صفقة. كلها رسائل بالعربي.

وقّفه بـ `Ctrl + C`. الصفقات المفتوحة تبقى محفوظة وتكمّل لما تشغّله مرة ثانية.

### ب) سوّ المشروع على Railway
1. ادخل **railway.com** وسجّل دخول بحساب GitHub.
2. اضغط **New Project** ← **Deploy from GitHub repo** ← اختار `diyarhussein28/ai-trading`. لو ما ظهر، اضغط **Configure GitHub App** واسمح له بالمستودع.
3. Railway يقرأ `Dockerfile` و`railway.json` بنفسه، وفيها: نسخة وحدة، وفحص `/health`، وإعادة تشغيل عند الفشل.

### ج) أضف قاعدة بيانات Postgres
داخل المشروع اضغط **+ New** ← **Database** ← **PostgreSQL**.

> **لا تشغّله بدون Postgres.** ملف SQLite داخل Railway ينمسح مع كل نشر جديد، ويضيع اختبارك.

### د) المتغيرات (Variables)
اضغط على خدمة البوت (مو Postgres) ← **Variables** ← أضف:

| الاسم | القيمة |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (اكتبها كذا بالضبط، تربطها بقاعدة البيانات) |
| `ANTHROPIC_API_KEY` | مفتاحك |
| `CLAUDE_VOTE_MODEL` | `claude-haiku-5-5` |
| `CLAUDE_REVIEW_MODEL` | `claude-opus-5-5` |
| `X_BEARER_TOKEN` | توكن X |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | من 3ج |
| `SOLANA_RPC_URL` | اختياري |
| `DASHBOARD_TOKEN` | **إلزامي هنا** |
| `CONFIG_PATH` | `config/v7.yaml` |
| `ALLOW_LIVE` | `no` |

لا تضيف `PORT`، لأن Railway يحطه تلقائياً. بعدها اضغط **Deploy**.

### هـ) الرابط العام
**Settings** ← **Networking** ← **Generate Domain**. يعطيك رابط شكله `xxx.up.railway.app`.
- `https://xxx.up.railway.app/health` لازم يرجع `{"ok": true, ...}`.
- لوحة التحكم: `https://xxx.up.railway.app/?token=كلمة_السر`

### و) تأكد إنه شغّال صح
- **Deployments ← View Logs**: تشوف `dashboard on http://localhost:8080 (version V7, paper, agents=llm)` وما فيه أخطاء.
- **Settings ← Replicas = 1**. لا ترفعها أبداً، لأن نسختين تعني كل صفقة تتكرر مرتين، وهذا خطأ V1 في الفيديو. حتى لو صارت بالغلط، النسخة الثانية تطلع بنفسها بسبب القفل.
- **وقّف النسخة المحلية** على جهازك وقت ما Railway شغّال، عشان ما تدفع تكلفة الذكاء الاصطناعي وX مرتين.

## 7) اختبار الـ 100 صفقة الحقيقي (الأهم)

### قبل ما تبدأ: جمّد الإعدادات

```bash
git tag v7-test-100
```

```bash
git push origin v7-test-100
```

**القاعدة الذهبية:** لا تعدّل `config/v7.yaml` أثناء الاختبار. لو عدّلته بدون ما تغيّر `version`، يطلع في اللوحة شريط أحمر مكتوب فيه إن الإعدادات تغيّرت في نص الاختبار.

### المتابعة اليومية (5 دقائق)
1. افتح اللوحة وشوف عداد **الـ 100 صفقة** و**الحكم**.
2. كل 10 صفقات يجيك تقرير 📊 على تيليجرام فيه نسبة الإصابة، ونطاق الثقة (95% CI)، وProfit Factor، والربح، وأسوأ صفقة. **لا تغيّر أي شيء بناءً عليه.**
3. شيك **التكاليف مقابل الربح**: لو التكاليف (Claude + X + الاستضافة) أكبر من الربح الورقي، فالإستراتيجية خسرانة حتى لو الصفقات رابحة.
4. لو جاك 🛑 **إيقاف مبكر**، النظام وقف الدخول بنفسه. يصير لما يكون Profit Factor أقل من 0.8 بعد 40 صفقة، أو التراجع أكبر من 35%.

### شروط النجاح (لازم تتحقق كلها، واللوحة تحسبها لك)
- الحد الأدنى لنطاق الثقة لنسبة الإصابة أعلى من نسبة التعادل.
- Profit Factor أكبر من أو يساوي 1.5 بعد التكاليف.
- أكبر تراجع ≤ 25% من رأس المال الورقي (0.5 SOL).
- ما فيه صفقة وحدة تشكّل أكثر من 30% من الربح.
- صفقات الدرجة 80+ أفضل من صفقات 70–79.
- تكاليف التشغيل أقل من الربح الورقي.

### كم ياخذ؟
يعتمد على السوق. البوت صعب الإقناع عن قصد، فممكن يأخذ **أيام إلى أسابيع**. لا تستعجل.

## 8) بعد الاختبار

**✅ ناجح:** الخطوة الجاية حسب المخطط (القسم 17) هي بناء طبقة تنفيذ حقيقية تُراجَع بعناية: محفظة منفصلة فيها مبلغ صغير بس، وحد أقصى للانزلاق، وحماية MEV، و50 صفقة صغيرة جداً أول. هذا **غير موجود في الكود** ويحتاج عمل منفصل.

**⚠️ غير حاسم:** ما فشل أي شرط، لكن فيه شرط ما توفرت له بيانات كافية عشان ينحكم عليه. أشهرها المعايرة: لو أغلب الدرجات فوق 80، تكون فئة 70–79 فيها أقل من 5 صفقات. معناها إن الدرجة **ما ثبت إنها تفيد**، والمخطط يقول وقتها ارجع لحجم ثابت. كمّل 50 صفقة إضافية، أو جرّب V8 بحجم ثابت.

**❌ فشل أو توقف مبكراً:** سوّ **V8** بتغيير **واحد بس**:

```bash
cp config/v7.yaml config/v8.yaml
```

داخل `config/v8.yaml` غيّر `version: V8` والشيء الوحيد اللي تبي تجربه، مثلاً `max_top10_holders_pct: 25`. وفي Railway Variables غيّر `CONFIG_PATH=config/v8.yaml`. البيانات القديمة تبقى، وجدول الإصدارات في اللوحة يقارن V7 بـ V8.

أفكار V8 من المخطط (جرّب وحدة كل مرة):
1. بيع 50% عند +40% وترك الباقي بوقف متحرك.
2. فلتر أقسى للـ Rug: أكبر 10 حاملين ≤ 25%، والمطلعين (insiders) ≤ 10%.
3. وكيل رابع يفحص المحافظ الرابحة.
4. تحليل الأداء حسب ساعة اليوم.

## 9) حل المشاكل

| المشكلة | السبب الغالب | الحل |
|---|---|---|
| ولا صفقة بعد يوم كامل | X غير مفعّل و`on_missing: pass` | أضف `X_BEARER_TOKEN` أو استخدم `degrade` |
| رسالة "خلصت ميزانية X" | وصلت حد الصرف | طبيعي ويرجع بعد ساعة أو يوم. لا ترفع الحد بدون حساب |
| رقم **إطلاقات شافها** ثابت | انقطاع PumpPortal | البوت يعيد الاتصال تلقائياً. يجيك تنبيه ⚠️ بعد دقيقتين |
| `/health` يرجع 503 | حلقة المسح أو قاعدة البيانات متوقفة | شوف Logs. Railway يعيد التشغيل تلقائياً |
| "Another instance holds the lock" | نسختين شغّالة | خلّ Replicas = 1 |
| "agents.backend is 'llm' but no Anthropic credentials" | المفتاح ناقص | أضف `ANTHROPIC_API_KEY` |
| شريط أحمر "الإعدادات تغيّرت في نص الاختبار" | عدّلت الإعدادات بدون تغيير الإصدار | رجّع التعديل أو غيّر `version` |
| `401` على اللوحة | ناقص `?token=` | أضفه للرابط |
| كثير من الرفض "pool holds only $X of SOL" | عملات مسحوبة سيولتها | هذا الفلتر يحميك، لا تشيله |

## 11) تحذيرات لا تتجاهلها
- **نسبة الـ 80% في الفيديو هي 8 من 10 صفقات.** النطاق الحقيقي ممكن يكون من 49% إلى 94%. لا تحكم من أول 10 صفقات.
- **لا تستخدم سحب X بالكوكيز.** يخالف الشروط، ولو انحظر الحساب يخرب الاختبار.
- **لا ترفع مفاتيحك على GitHub أبداً.**
- **عملات الميم أغلبها يروح للصفر.** لا تحط إلا مبلغ تتحمل تخسره كله.
- **الضرائب:** في ألمانيا، أرباح العملات اللي تبيعها قبل ما تكمّل سنة خاضعة للضريبة. احتفظ بسجل كامل، واللوحة تسجّل كل صفقة.
